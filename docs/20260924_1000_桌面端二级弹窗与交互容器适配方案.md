# 桌面端二级弹窗与交互容器适配方案（高复用·极简改版）

> **规划定位**：**「组件同源，容器响应」（Same Components, Adaptive Containers）**。  
> **核心宗旨**：**最大化复用移动端已完成的表单、逻辑与视图组件**，以最小改动量将移动端「底部抽屉（BottomSheet）」和「全屏次级页」升级为符合桌面规范的「居中卡片（Dialog）」与「右侧抽屉（SideSheet）」。  
> **红线原则（最高优先级）**：**移动端零改动、零回归（Mobile Zero-Regression）**。所有改动必须以响应式断点（`AppBreakpoints.isWide`）为绝对边界，严禁影响手机端/窄屏下的现有视觉与交互。

---

## 1. 现状痛点与人机工程学分析

在当前版本中，部分二级功能在桌面端（宽屏 $\ge 600\text{dp}$ / 1080P / 2K）呈现出以下不良体验：

| 二级弹窗 / 交互场景 | 移动端现状 | 电脑端现状痛点 | 人机工程学缺陷 |
|---|---|---|---|
| **设置（Settings）** | 路由 `push('/settings')` 全屏推入 | 全屏展开，巨幅留白，主工作区被完全遮盖 | 桌面用户只是想改个壁纸或看一眼同步，却被整页打断，无法边看界面边调设置 |
| **新建自定义视图** | 路由 `push('/custom_view/new')` 全屏推入 | 全屏单列展开，两边空旷，丢失当前列表上下文 | 缺乏辅助面板质感，保存后需要全屏退回 |
| **新建清单或文件夹** | `showModalBottomSheet`（底部大抽屉） | 从屏幕最底端横向拉满（1920px 宽）升起 | 视线在屏幕上方操作鼠标，弹窗却在最底下，横向被拉伸变形，极不自然 |
| **四象限视图范围筛选** | `showModalBottomSheet`（底部大抽屉） | 从屏幕底部横贯整个屏幕升起，树状清单变形 | 桌面端四象限是 2×2 网格，底部升起抽屉严重破坏网格视野，操作动线冗长 |
| **自定义视图列筛选设置** | 宽屏已自适应居中 `Dialog`，手机走 `BottomSheet` | **目前体验优秀的标杆样例**（见 `filter_criteria_sheet.dart`） | 结构紧凑、操作聚焦，是其他表单弹窗改造的绝佳参考 |

## 2. 电脑端三大交互容器范式（选型决策）

根据桌面操作系统的设计指南（macOS Human Interface Guidelines & Windows Fluent Design）以及一流效率应用（Linear, TickTick Desktop, Notion, Apple Reminders）的实践，桌面端不应该存在「从屏幕底沿贯通弹起的 BottomSheet」。

我们将二级交互清晰归纳为 **三大容器范式**：

```
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                                 桌面端二级交互容器规范                                    │
├─────────────────────────┬───────────────────────────────┬───────────────────────────────┤
│ 范式 A：右侧抽屉         │ 范式 B：居中模态卡片           │ 范式 C：就近锚定浮层          │
│ (Modal Side Sheet)      │ (Centered Adaptive Dialog)    │ (Anchor Popover / Menu)       │
├─────────────────────────┼───────────────────────────────┼───────────────────────────────┤
│ · 宽度 480~520dp 固定    │ · 宽度 440~520dp 居中卡片     │ · 紧贴触发按钮展开           │
│ · 拥有完整纵深与子页面   │ · 最大高度限制 80~85% 屏高     │ · 适合轻量单值选择           │
│ · 左侧主工作区清晰可见   │ · 专注填写/快速配置，点完即走 │ · 点击外部即刻收起           │
│                         │                               │                               │
│ 适用：                   │ 适用：                        │ 适用：                        │
│ 1. 全局设置 (Settings)  │ 1. 新建清单/文件夹            │ 1. 任务快捷右键菜单          │
│ 2. 自定义视图新建/编辑  │ 2. 四象限范围筛选             │ 2. 优先级/颜色快速点选       │
│ 3. 任务详情内联检视     │ 3. 自定义视图列筛选(已实现)   │                               │
│                         │ 4. 背景壁纸选择器             │                               │
│                         │ 5. 快照与备份历史列表         │                               │
└─────────────────────────┴───────────────────────────────┴───────────────────────────────┘
```

## 3. 具体功能改造方案与代码复用剖析

### 3.1 设置（Settings）
- **电脑端推荐形态**：**右侧抽屉（Modal Side Sheet，宽度 `AppTokens.sideSheetWidth` = 480dp）**。
- **行为设计**：
  - 用户在常驻侧边栏左下角点击「设置」图标；
  - 侧边栏与主工作区不动，设置面板平滑从屏幕右侧滑入，附带轻微半透明遮罩；
  - 支持内部层级跳转：点击「WebDAV 同步」或「标签管理」，在 Side Sheet 内部以导航栈平滑切换（`_SettingsSheetNavigator` 已实现！）；
  - 支持按键盘 `Esc` 键、点击左侧空白遮罩区、或点击右上角 `✕`，设置面板一键收起，主工作区状态丝毫受干扰。
- **组件复用情况（复用率 95%）**：
  - 仓库内已存在现成组件：`lib/features/settings/widgets/settings_side_sheet.dart`（`showSettingsSideSheet`）和 `lib/shared/widgets/modal_side_sheet.dart`；
  - `SettingsBody` 已经解耦（接受 `onOpenSync`, `onOpenTags`, `onOpenHelp`）；
  - **改动仅需 1 处**：在 `lib/shared/widgets/scope_nav_content.dart` 的底部设置按钮点击处，增加断点判断：
    ```dart
    onPressed: () {
      if (AppBreakpoints.isWide(context)) {
        showSettingsSideSheet(context);
      } else {
        _navigateTo('/settings', isPush: true);
      }
    },
    ```

- **电脑端推荐形态**：**右侧抽屉（Modal Side Sheet，宽度 `AppTokens.sideSheetEditorWidth` = 520dp）**。
- **行为设计**：
  - 用户在侧边栏「自定义视图」区域点击「+」添加按钮（或在自定义视图页面右上角点击编辑）；

  - 用户点击某一列的「筛选规则」，在最顶层弹出一个居中 Dialog（见 3.5），配置完成后关闭 Dialog，回到 Side Sheet；
  - 点击「保存」后抽屉自动收起，侧边栏与中间工作区无缝刷新。
- **组件复用情况（复用率 98%）**：

  - **改动仅需 1 处**：在 `scope_nav_content.dart` 中的 `onAdd` 入口，添加宽屏分流：
    ```dart
    onAdd: () {

        showCustomViewEditorSideSheet(context);

    ```

### 3.3 新建清单或文件夹（Create List or Folder）
- **电脑端推荐形态**：**居中自适应模态卡片（Centered Adaptive Dialog，宽度 460dp）**。
- **行为设计**：
  - 用户在侧边栏「清单与文件夹」点击「+」添加文件夹，或在底部点击「新建清单」；
  - 屏幕居中弹出圆角卡片（`radiusDialog` = 16dp），四周带柔和双层阴影；
  - 顶部保留「取消」、「清单/文件夹 分段切换器」、「完成」；
  - 表单区域完整呈现：清单名称输入框（聚焦自动选中）、预设主题色圆点、分类图标网格、所属文件夹下拉、背景壁纸选择项；
  - 键盘友好：支持 `Enter` 键快速提交，`Esc` 键取消。
- **组件复用情况（复用率 95%）**：
  - 现有 `CreateListFolderSheet`（位于 `lib/features/projects/widgets/create_list_folder_sheet.dart`）本身就是一个独立的 `ConsumerStatefulWidget`，表单校验、保存逻辑、色彩/图标/壁纸联动已经极为完善；
  - **改动仅需改造入口函数 `showCreateListFolderSheet`**：
    ```dart
    Future<T?> showCreateListFolderSheet<T>({
      required BuildContext context,
      CreateType initialType = CreateType.list,
      String? initialFolderId,
      Project? editingProject,
      Folder? editingFolder,
      bool useRootNavigator = true,
    }) {
      if (AppBreakpoints.isWide(context)) {
        return showDialog<T>(
          context: context,
          useRootNavigator: useRootNavigator,
          builder: (dialogCtx) => Dialog(
            backgroundColor: Colors.transparent,
            insetPadding: const EdgeInsets.symmetric(horizontal: 24, vertical: 32),
            child: ConstrainedBox(
              constraints: const BoxConstraints(maxWidth: 480, maxHeight: 720),
              child: ClipRRect(
                borderRadius: BorderRadius.circular(AppTokens.radiusDialog),
                child: CreateListFolderSheet(
                  initialType: initialType,
                  initialFolderId: initialFolderId,
                  editingProject: editingProject,
                  editingFolder: editingFolder,
                  isDialog: true, // 告知内部微调边距和圆角
                ),
              ),
            ),
          ),
        );
      }

      // 移动端/窄屏完全保持原有的 showModalBottomSheet + KeyboardInsetBuilder
      return showModalBottomSheet<T>(...);
    }
    ```
  - 移动端 100% 走原有分支，零改动零风险！

### 3.4 四象限视图的范围筛选（Quadrant Scope Filter）
- **电脑端推荐形态**：**居中模态卡片（Centered Adaptive Dialog，宽度 480dp，最大高度 680dp）**。
- **为什么不使用下拉 Popover？**
  - 四象限的清单范围可能多达数十个，内含文件夹层级树（`UnifiedHierarchicalFolderContainer`）、全选/反选预设、以及「显示已完成」开关；
  - 如果使用下拉气泡（Popover），在笔记本小屏幕（如 13 寸 1280×800）很容易向下溢出屏幕，产生双滚动条与遮挡问题；
  - 居中卡片（Dialog）视觉居中聚焦、空间宽裕、层次分明，与系统的设计系统完美融合。
- **行为设计**：
  - 用户在四象限顶栏 FilterBar 点击「范围筛选」胶囊按钮；
  - 屏幕居中淡入圆角卡片，隐藏移动端底部的抓手条（Grabber）；
  - 树形勾选列表支持鼠标滚轮滚动，底部一键「完成」或点击背景遮罩保存退出。
- **组件复用情况（复用率 98%）**：
  - 核心勾选树控件 `UnifiedHierarchicalFolderContainer` 100% 复用；
  - `quadrantFilterProvider` 状态管理 100% 复用；
  - 改造入口 `QuadrantScopeFilterSheet.show(context)`，增加 `if (AppBreakpoints.isWide(context))` 走 `showDialog`。

### 4.2 维护难度评估（Maintainability）
1. **单一事实源（Single Source of Truth）**：
   - 表单的状态、验证、保存以及业务逻辑代码 **零复制（Zero Duplication）**；
   - 移动端和电脑端共用同一套 Widget 类（如 `CreateListFolderSheet`、`_FilterCriteriaForm`、`SettingsBody`、`UnifiedHierarchicalFolderContainer`）；
   - 后续任何字段增减、业务规则修改，只需改动一处，双端同步生效，维护成本为零新增。
2. **测试与回归风险（Zero Mobile Regression）**：
   - 分流严格建立在 `AppBreakpoints.isWide(context)` 之上；
   - 手机端屏幕宽度 $<600\text{dp}$，走完全未经修改的原始 `showModalBottomSheet` 路径；
   - 单元测试与现有 UI 测试均不受影响。
