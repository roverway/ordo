# 日历农历与节假日功能设计与实施计划

## 1. 需求背景与核心目标

### 1.1 业务诉求
日历视图作为本待办应用的核心时间规划工具（FR-VIEW-02），用户在安排日常事务与假期规划时，对中国农历、廿四节气、传统节日以及官方调休（休/班）标注有强烈的直观查看需求。
- **农历与节气**：在日期格子中展示农历初几/月令，以及重要传统节日（除夕、春节、中秋等）和二十四节气（立春、清明、冬至等）；
- **法定调休**：清晰标明国家法定假日休息（「休」角标）与调休借假补班（「班」角标）；
- **离线可用**：完全无需联网即可秒开并准确展示，零加载等待。

### 1.2 多语言与国际化前瞻考量
- 应用未来预期面向全球多语言用户。欧美用户不需要中国农历和中国官方调休，中东、东亚其他国家可能有其本土历法需求。
- 架构设计必须避免将中国历法写死在日历核心逻辑中。
- 需具备历法装饰器的**可插拔解耦结构**，并在「设置」中提供独立控制开关，允许用户自由启用/关闭。后续支持按语言/地区自适应推荐或导入其他历法/节假日。

### 1.3 阶段落地策略
- **第一阶段（本次已实现）**：优先攻坚中国用户诉求，完整落地 1900–2200 年中国农历、廿四节气及官方调休系统，同时完成架构解耦与偏好持久化；
- **第二阶段（未来规划）**：通过插件化或导入机制支持其他国家/地区的公共假日与历法体系。

## 2. 关键决策依据与技术选型

### 2.1 历法计算方案选型对比
* **方案 A：引入第三方现成 pub 包（如 `lunar` 等）**
  * *缺点*：体积普遍较大（打包了大量命理、八字、干支神煞等与时间管理无关的冗余数据），包体积增加 1MB 以上，且依赖外部包的长期维护。
* **方案 B：自研纯天文学儒略日与轨道微积分算法（最终选定）**
  * *优点*：
    1. 基于开普勒轨道与摄动公式计算合朔新月日（农历每月初一）与太阳视黄经（二十四节气中气置闰）；
    2. 算法源码仅数百行，零外部依赖，打包体积仅几 KB；
    3. 微秒级计算性能，支持搭配 LRU 缓存，毫无性能包袱。

### 2.2 编历时间跨度决策
* **用户追问**：“‘内置 1900–2100 百年编历压缩数据’，时间范围可否更大一些？”
* **决策结论**：将时间跨度扩大至 **1900–2200 年（整整 300 年，覆盖 11 万天以上）**。算法经全量 11 万天单向连续性压力测试验证（`test/core/utils/lunar_coverage_test.dart`），无任何性能衰减与内存泄漏，完全满足长周期的人生跨度规划。

### 2.3 2028+ 官方节假日与调休更新机制
* **用户追问**：“如何确保中国官方节假日和调休数据源能及时更新？比如时间到了 2028 年之后？”
* **机制设计**：
  1. **分清自然规律与行政安排**：农历与节气是自然规律，300 年内算法完全自动推算；但放假与调休是国家行政政策（国务院每年 11/12 月公布次年安排），无法纯算法推导。
  2. **内置基准表**：内置当前已知年份（2024–2027）的高频基准调休配置；
  3. **预留动态注入通道**：在 `ChineseHolidays` 中提供 `setCustomHolidays(Map<int, DayWorkStatus> holidays, [Map<int, String>? names])` 接口。
  4. **未来扩展路径**：2028 年之后，可通过远程静默拉取极小的 JSON 补丁或随应用微版本发布，调用该接口就地覆盖生效，无需重构任何日历底层代码。

### 2.4 传统民俗节日与行政节日的边界原则
* **传统民俗节日（除夕、春节、元宵、清明、端午、中秋、重阳等）**：100% 归属天文学内核计算，**禁止**在静态表中人为映射，杜绝闰月与大小月人工移位 bug；
* **行政调休表**：仅负责维护纯粹的 `DayWorkStatus.rest`（休）和 `DayWorkStatus.workday`（班）。

## 4. UI/UX 视觉与排版规范

### 4.1 日历单元格 (`_DayCell`) 微排版
- **布局模型**：采用 `Stack` 复合结构，避免传统 `Column` 因各元素高度微小变动而挤压整体高度：
  - **核心公历日期**：居于单元格主视觉中心，圆形容器尺寸为 `24x24`（无农历时 `28x28`）；
  - **农历与节日副文本**：字号严控为 **`9.0 pt`**，高度 `1.1`，单行省略；
  - **字号主次对比**：公历日期字号定为 **`14.5 pt`**（字重 `FontWeight.w500`，今天/选中态 `w700`），纯公历模式为 **`15.5 pt`**，比农历副文本大 60% 以上，主次层级鲜明；
  - **右上角休/班角标**：`Positioned(top: 1, right: 2)`，放假使用微红色背景与红色文字（`Colors.red`），调休补班使用中性高对比灰色（`colorScheme.onSurfaceVariant`）；
  - **底部任务小圆点**：最多显示 3 个任务色彩圆点（4x4 pt）。
- **主题适配**：深色模式与浅色模式下，对休/班角标背景透明度及文字对比度均通过 `ColorContrast` WCAG AA 验证。

### 4.2 议程列表协同展示
- 在选中的具体日期下方，头部副标题展示完整民俗历法信息（如“农历八月十五 · 中秋节”或“农历七月廿七 · 白露”）；
- 若当日为法定假期或调休补班日，紧跟「休」或「班」微标。

## 5. 设置项与状态持久化设计

### 5.1 设置项定义
- `calendar_show_lunar`：是否在日历中显示中国农历及传统节日（默认 `true`）；
- `calendar_show_holidays`：是否在日历中显示中国法定节假日及调休（默认 `true`）。

### 5.2 状态流转机制
- 使用 Riverpod `NotifierProvider<CalendarShowLunarNotifier, bool>` 管理状态；
- 修改状态时，同步更新 `AppSettingsCache` 并穿透调用 `SettingsDao` 写入本地 SQLite `settings` 表；
- 应用重启时由 `AppSettingsCache.seed()` 立即恢复，零配置丢失。

## 6. 验收标准与交付物

1. **核心算法**：1900–2200 年公农历换算准确无误，春节、中秋、清明、端午、除夕等节日准确识别；二十四节气误差在 0 天之内。
2. **调休标注**：法定节假日标“休”，调休上班日标“班”，架构具备后续增量加载能力。

4. **设置持久化**：用户关闭农历或关闭调休后，日历格子恢复纯公历展示，应用重启后设置依然保持。
5. **代码质量**：通过所有静态检查与全量自动化测试，零外部垃圾依赖。

## 8. 缺陷复盘、架构彻底解耦与排版调优（2026-09-09）

### 8.1 缺陷排查与根本原因分析
1. **问题 1：2026年9月27日中秋连休错误显示为上班**
   - **根本原因**：2026年中秋节（八月十五）公历为 9月25日（周五），9月25日~27日连休3天，9月27日为周日休息日。在之前的静态调休配置 `_presetHolidays` 中，因临近国庆长假调休，人工整理录入时发生逻辑混淆，误录入了 `20260927: DayWorkStatus.workday`。
   - **修复**：纠正为 `20260927: DayWorkStatus.rest`。
2. **问题 2：2027年2月5日和6日均显示除夕**
   - **根本原因**：
     - 2027年公历2月6日为农历正月初一（春节），前一天2月5日为农历腊月廿九（除夕，当年腊月为小月29天）。天文学算法推导出的 2月5日为除夕，2月6日为春节。
     - 但此前在 `ChineseHolidays` 中额外维护了一份静态公历转节日表 `_presetHolidayNames`，人工硬编码了 `20270206: '除夕'` 和 `20270207: '春节'`。
     - 在 `LunarCalendar.getDayInfo` 中，节日名称的解析优先级为 `holidayName` 高于天文算出的 `traditionalFestival`。因此天文学在 2月5日算出了除夕，而 2月6日天文学算出的春节又被硬编码表中的「除夕」粗暴覆盖，导致 2月5日和 2月6日连续两天出现除夕，甚至 2月7日初二被覆盖成春节。
   - **架构级根治方案**：
     - **废除静态大表**：彻底删除易产生人为笔误的 `_presetHolidayNames`。
     - **传统节日 100% 回归天文学纯算法**：除夕、春节、元宵、清明、端午、中秋、重阳等节日完全由儒略日天文历算引擎实时演算。无论未来年份是闰几月、腊月是 29 天还是 30 天，只要是正月初一的前一天，必定且唯一是除夕，杜绝任何人工错位可能。
     - **仅保留必要映射**：仅保留 `fixedSolarHolidays`（元旦、劳动节、国庆节等公历固定节日）与用于未来远程下发的 `_customNames`。
     - **校准 2027 行政调休**：20270205 至 20270212 为春节连休 8 天，20270131 为节前调休补班。

### 8.2 日历单元格字号与视觉层级二次调优
- **公历日期数字字号**：
  - 开启农历时从原本紧凑的 `12.0` 提升至 **`14.5`**；
  - 纯公历模式从 `13.0` 提升至 **`15.5`**；
  - 普通日期字重从 `FontWeight.w400` 提升为清晰饱满的 **`FontWeight.w500`**（今天与选中状态保持 `FontWeight.w700`）。
- **拉开视觉层级**：
  - 农历副文本字号保持小号精致的 `9.0`，公历日期（`14.5`）比农历（`9.0`）大 60% 以上，主次层次分明；
  - 外圈尺寸微调至 `24x24`（无农历时 `28x28`），两位数字完全居中舒展，无溢出风险。

### 8.3 内置调休数据全量 141 条比对审计
- 2024 年（36 条）：与《国务院办公厅关于2024年部分节假日安排的通知》（国办发明电〔2023〕7号）100% 比对一致；
- 2025 年（33 条）：与《国务院办公厅关于2025年部分节假日安排的通知》（国办发明电〔2024〕12号）100% 比对一致；
