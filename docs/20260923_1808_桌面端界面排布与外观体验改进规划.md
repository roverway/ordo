# 桌面端界面排布与外观体验改进规划（高复用·极简改版方案）

> **规划定位**：**「组件同源，容器响应」（Same Components, Adaptive Containers）**。  
> **核心宗旨**：**最大化复用移动端已完成的成熟组件与设计资产**，以**最小的代码改动量**解决宽屏浪费问题。  
> **红线原则（最高优先级）**：**移动端零改动、零回归（Mobile Zero-Regression）**。所有改动必须以响应式断点（`AppBreakpoints.isWide`）或平台守卫为绝对边界，**严禁对移动端（窄屏 / 手机端）的现有外观、交互、动画、行高、留白及操作流程产生任何改变**。

---

## 0. 移动端零回归守则与防护机制（最高准则）

为确保手机端体验 100% 保持现状，我们在工程与架构层面制定以下铁律：

| 维度 | 移动端现状（严格保持不变，零改动） | 宽屏桌面端（仅在此分支生效） |
|---|---|---|
| **导航形式** | **纯净单屏无侧栏**，点击顶栏大标题平滑升起 [`ScopeSwitcherSheet`](file:///mnt/Data/Personal/04_others/My_Development/todo/lib/shared/widgets/scope_switcher_sheet.dart) 底部抽屉 | 根容器 [`AppShell`](file:///mnt/Data/Personal/04_others/My_Development/todo/lib/shared/widgets/app_shell.dart) 常驻左侧 [`AppSidebar`](file:///mnt/Data/Personal/04_others/My_Development/todo/lib/shared/widgets/app_sidebar.dart)（复用抽屉内容） |
| **新建任务** | **右下角悬浮胶囊 FAB** 保持不变，底部 `130dp` 防遮挡留白严格保留 | 隐藏 FAB，在顶栏放置紧凑「+ 新建」按钮，消灭底部空白 |
| **任务编辑** | 点击任务行继续保持**全屏转场 Push（或既有底部弹出）**，返回箭头一键返回 | 点击任务行右侧直接内联展开检视区（无遮罩并发操作） |
| **列表宽度** | 满屏拉伸（20dp 边距），适应手机单手触达与竖屏浏览 | 增加 `maxWidth: 820dp` 居中约束，防止桌面巨屏行长过长 |
| **项目概览** | 保持经典**单列垂直卡片流**滚动 | 升级为自适应 2~3 列网格卡片 |
| **断点防线** | 仅当 `!AppBreakpoints.isNarrow(context)`（即宽度 $\ge 600\text{dp}$ / $\ge 768\text{dp}$）时启用宽屏排布；手机设备默认落入窄屏分支，执行原汁原味的移动端代码路径 | — |

## 1. 核心思路：从“另起炉灶”到“资产复用”

此前规划中存在部分为桌面端单独设计新控件（如单独的桌面专属内联输入条、全新的侧边栏体系）的想法，这不仅增加了开发和测试维护工作量，还容易造成移动端与桌面端的体验割裂。

经对当前 `lib/` 现有资产的深度排查，**移动端现有组件的质量极高，只需通过“容器与排布转换”，即可直接化身为优秀的桌面端体验**：

| 体验维度 | 移动端现有成熟资产 | 桌面端复用与呈现方式 | 预期工作量 |
|---|---|---|---|
| **导航与切换** | `ScopeSwitcherSheet`（系统组、自定义视图、文件夹与项目树、待办计数、拖拽排序、操作菜单） | 抽取其核心内容为 `ScopeNavContent`：**移动端继续作为底弹窗展示，桌面端直接作为左侧常驻侧边栏（Sidebar）渲染** | **极低**（同一套列表、样式、事件 100% 复用） |
| **任务编辑/查看** | `TaskEditor` + `TaskEditPage`（项目选择、标题、子任务树、日期时间、优先级、描述、删除） | 宽屏下直接作为**右侧内联检视器（Inspector）或无遮罩侧滑面板**嵌入页面右侧，中间列表点击某行直接载入右侧，无需全屏遮罩跳转 | **低**（底层表单与组件 100% 复用，仅调整外层呈现容器） |
| **新建任务** | `TaskCreateSheet`（圆角卡片、日期/优先级快捷选项、子任务输入） | 桌面端将右下角 FAB 按钮平移至**顶栏操作区**（`+ 新建任务` 胶囊按钮），点击呼出居中卡片弹窗或直接激活右侧编辑器，移动端 FAB 完全保留 | **极低**（直接复用 `TaskCreateSheet`，仅调整触发入口） |
| **主任务列表** | `TaskListPage` + `TaskTree` + `SimpleTaskTile` + `PageHeroHeader` + `FilterChipsBar` | 组件全量复用。桌面端通过容器自适应：**限制列表最大可读宽度（`maxWidth: 820dp` 居中）**，消灭千像素长文本横向漂移；顶栏移除点击呼出底弹窗行为，改为展示侧栏折叠开关 | **极低**（仅外层加约束与顶栏回调判断） |
| **项目概览** | `ProjectsPage` + `ProjectCard` | 复用现有的 `ProjectCard`，仅在宽屏下将单列竖排滚动改为 **自适应 2~3 列网格（SliverGrid）**，移动端维持单列不变 | **极低**（几行布局代码分支） |
| **四象限与日历** | `QuadrantGrid`（2×2 田字格） + `CalendarPage`（双栏日历） | 现有代码内部已有宽屏排布支持，只要外层套入常驻导航侧边栏，即可天然成为舒展的桌面工作区 | **近乎零**（直接开箱即用） |

## 2. 界面组件排布与外观方案（极简响应式双模）

### 2.1 整体布局骨架：`AppShell` 条件化分流

在 `AppShell` 中根据屏幕宽度进行严格分支：
- **窄屏（`AppBreakpoints.isNarrow(context)`，手机端 / 移动端）：**
  ```dart
  if (isNarrow) {
    // 100% 保持现有原样，直接透传背景与 child，不挂载任何侧边栏
    return AppBackgroundWrapper(child: child);
  }
  ```
- **宽屏（`!AppBreakpoints.isNarrow(context)`，桌面端 / 平板）：**
  ```
  ┌──────────────────────┬────────────────────────────────────────────┬────────────────────────────┐
  │ 左栏：常驻导航       │ 中栏：任务主工作区                          │ 右栏：任务检视面板         │
  │ (ScopeNavContent)    │ (TaskListPage / 限制最大行宽)               │ (TaskEditPage 内联渲染)    │
  │                      │                                            │                            │
  │ · 240~260dp 固定宽   │ · 居中显示，自适应填充                      │ · 380~420dp 固定宽         │
  │ · 完整复用现有切清单   │ · 顶栏保留 Hero 进度环与 Chips 筛选         │ · 点击任务即时加载         │
  │   和文件夹树组件      │ · 顶栏右侧设置「+ 新建任务」按钮            │ · 点击 X 或失焦直接收起     │
  │ · 底部设置与同步状态  │ · 鼠标悬停任务行高亮反馈                    │ · 无深色遮罩，列表保持可操作│
  └──────────────────────┴────────────────────────────────────────────┴────────────────────────────┘
  ```

### 2.2 关键组件排布改造细节（严守分支隔离）

#### 1. 左栏：复用 `ScopeSwitcherSheet` 内容转为 `AppSidebar`
- **复用点**：
  `lib/shared/widgets/scope_switcher_sheet.dart` 内部已经写好了极其完善的系统视图项（今天、收集箱、日历、四象限）、自定义视图动态加载、文件夹展开/折叠、拖拽重排、以及底部的同步状态与设置。
- **改造方式**：
  提取其内部滚动列表为公共控件 `ScopeNavContent({required bool isDrawer})`。
  - **移动端**：继续在 `showModalBottomSheet` 中展示，抓手、圆角、半透遮罩一律保持现状。
  - **桌面端**：放入宽度为 `260dp` 的固定左侧栏，右侧带 1px 细边框（`borderSubtle`）。
- **用户收益**：无需学习新交互，移动端怎么整理清单，桌面端一模一样；且切换项目再也不需要弹窗。

#### 2. 中栏：任务列表限制舒适阅读行宽
- **复用点**：
  现有 `TaskListPage` 的分组折叠、`FilterChipsBar`、`SimpleTaskTile`、`TaskTree` 原样保留。
- **排布优化**：
  在宽屏模式下，用 `Center` + `ConstrainedBox(maxWidth: 820)` 将任务列表包裹起来。
  - **移动端**：继续占满屏幕宽度（左右 20dp padding），单手滑动顺畅；
  - **桌面端**：任务列表居中，左右留出对称的呼吸感留白，彻底解决标题在最左、时间在最右的横向视线疲劳；
- **FAB 与顶栏调整**：
  - **移动端**：右下角 FAB 保持原位，底部 `130dp` 占位继续生效；
  - **桌面端**：隐藏右下角 FAB，清除底部空白；在 `PageHeroHeader` 右侧放一个精致的 `FilledButton.icon`（`+ 新建`），点击呼出已有的 `TaskCreateSheet`。

#### 3. 右栏：任务编辑组件 `TaskEditor` 内联化
- **复用点**：
  直接复用现有的 `TaskEditPage`（底层为 `TaskEditor`）。
- **交互方式**：
  - **移动端**：点击任务行，继续走标准的页面 Push 或抽屉弹窗（100% 不变）；
  - **桌面端**：点击任务行时，中栏高亮该任务，右侧容器滑动展出 `TaskEditPage`，失焦自动同步，点击 `✕` 收起；中间任务列表保持完全可见可点击。

#### 4. 项目概览页 `ProjectsPage`：单列改网格
- **复用点**：
  现有的 `ProjectCard` 已经封装了项目颜色、进度条、待办任务统计和文件夹归属。
- **改造方式**：
  - **移动端**：保持原有的单列竖排卡片；
  - **桌面端**：使用 `SliverGrid.builder` 渲染为 2~3 列网格卡片。

## 3. 外观质感与多端统一（零新增样式风险）

1. **统一设计令牌（Design Tokens）**：
   桌面端排布直接使用 `lib/core/theme/app_tokens.dart` 已有的圆角、色彩、阴影、透明度令牌，绝不引入私有硬编码值，保证与手机端一致的干净极简现代风格。
2. **壁纸系统自适应**：
   桌面端分栏完全兼容已有的 `AppBackgroundWrapper`。当用户设置了全局壁纸或清单壁纸时：
   - 左侧栏与右侧检视区自动施加半透磨砂毛玻璃底色，与中间主列表区形成具有纵深的玻璃质感层次。
3. **鼠标光标与悬停状态**：
   复用既有的语义化透明度令牌 `alphaTintFaint`（0.06），为桌面端任务行与清单项补充鼠标 Hover 悬停浅底，不影响移动端触摸反馈。

## 4. 实施阶段规划（轻量、低风险、敏捷交付）

### 阶段一：导航组件复用与桌面双栏骨架（核心突破，解决大屏幕空旷）
- **改动范围**：
  1. 将 `ScopeSwitcherSheet` 中的核心列表抽为公共组件 `ScopeNavContent`。
  2. 在 `AppShell` 的宽屏分支挂载左侧常驻侧边栏；**移动端分支严格保留 `return AppBackgroundWrapper(child: child)`**。
  3. 任务列表外层在宽屏增加 `maxWidth: 820` 居中约束（移动端不加）。
  4. `ProjectsPage` 宽屏改自适应网格（移动端保留单列）。
- **验证标准**：
  - 手机端/窄屏模式运行，截图比对 100% 无任何视觉或操作变动；
  - 桌面宽屏下，侧边栏直接常驻，清单秒切，再无底部大弹窗。

### 阶段二：顶栏新建整合与消灭桌面 FAB 留白
- **改动范围**：
  1. 仅在宽屏下隐藏右下角移动端 FAB，清理列表底部的 `130dp` 留白；**移动端 FAB 与留白 100% 保持原样**。
  2. 桌面端顶栏右侧集成紧凑的「+ 新建」按钮，呼出现有的 `TaskCreateSheet`。
- **验证标准**：
  - 手机端 FAB 正常显示、正常新建、底部滑动正常；桌面端底部清爽。

### 阶段三：三栏内联检视器（双向联动）
- **改动范围**：
  1. 宽屏下点击任务行直接在右侧内联挂载现有的 `TaskEditPage`，消灭深色模态遮罩；**移动端仍保持原有的全屏/抽屉 Push 路由跳转**。
- **验证标准**：
  - 桌面端支持边看列表边改右侧任务；手机端单屏流转丝毫未动。
