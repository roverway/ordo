# 55 — UI 重构开发文档（定稿）

> 状态：**FINAL — 已与用户讨论定稿（2026-08-12）**。依据：`docs/ticktick-design-analysis.md`（滴答清单截图分析）× 当前实现 × 项目约束。
> 本文档是 UI 重构的唯一实施依据；改代码前先同步 `50-ui-ux.md` 与本档保持一致。

## 1. 背景与目标

当前 UI 已完成 M0–M3（导航壳、任务树、今日/日历/标签/搜索四视图、任务编辑页），整体为「Material 3 + 自定义令牌」风格。经与滴答清单（TickTick）实际截图逐屏对比，存在以下差距：

| 维度 | 滴答清单 | 本项目当前 | 差距 |
|---|---|---|---|
| 页面基底 | 浅灰背景 + 白色卡片，层次靠卡片区分 | M3 默认 surface 铺满，无卡片化 | 信息层级弱 |
| 任务行 | 白卡片、圆形复选框、标题+辅助信息紧凑排布 | 透明行 + M3 方形 Checkbox | 缺少滴答的轻快感 |
| 添加任务 | 底部弹窗 + 自动保存 + 键盘工具栏 | 独立全屏编辑页 | 移动端操作路径偏重 |
| 导航 | 侧边栏抽屉（清单分组 + 选中高亮） | 底部 5 tab / 宽屏 NavigationRail | 项目入口偏浅 |
| 快速新建 | 右下蓝色圆形 FAB | 无 FAB | 缺少主要操作入口 |
| 进度表达 | 进度圆环 + 百分比 | 无（仅派生徽标/进度条文案） | 派生状态表达不直观 |
| 同步状态 | — | 无（M4 未完成） | 需同步完成 |

**目标**：在不破坏现有功能与数据模型的前提下，将视觉与交互向滴答清单靠拢——「卡片化、轻量快速新建、更强的层级与状态可视性」，同时保持移动优先 + 桌面自适应、i18n、设计令牌三大硬约束。

## 2. 已定决策（D1–D5）

| 决策 | 结论 |
|---|---|
| **D1 导航模式** | 移动端（<600dp）改为**侧边栏抽屉**承载清单（项目）导航；宽屏（≥600dp）保留 NavigationRail。需更新 `FR-NAV-01` 与 `50-ui-ux.md` §4 |
| **D2 添加任务** | 移动端**新建任务用底部弹窗**（滴答式：清单选择+标题+选项行+自动保存）；**编辑已有任务保留全屏页**（字段多） |
| **D3 视觉基调** | **保留 M3 动态色**（种子色 #4A6CF7），仅调整页面基底为「浅灰底 + 白卡」+ 圆角 12–16 |
| **D4 任务行** | **圆形复选框**（完成=蓝色填充白勾）+ **卡片化行**，元信息内联紧凑排布 |
| **D5 实施节奏** | **分两批**：批 1 视觉层（纯表现）→ 验收 → 批 2 交互层 |

## 3. 导航与信息架构（D1 细化）

### 3.1 移动端（<600dp）：侧边栏抽屉

```
AppBar: [≡] 标题（当前清单名）        [搜索] [设置]
        └─ 汉堡打开抽屉

抽屉（宽 75–80% 屏宽，右侧半透明遮罩可点击关闭）：
├─ 顶部：应用名/Logo（无账号体系，不做头像）
├─ 系统组（无分隔线）：
│   今日（橙色图标）  收集箱（橙色图标）  日历（蓝色图标）  标签（蓝色图标）
├─ ── 细分隔线 ──
├─ 项目组（用户自定义清单）：
│   [颜色圆点] 项目名                    [未完成数]
│   （当前选中项：浅色背景 + 圆角 8–12 药丸高亮）
├─ ── 细分隔线 ──
└─ 底部：「+ 添加项目」（图标+文字）
```

- 底部 NavigationBar 精简为 **3 个系统入口：今日 / 日历 / 标签**（`FR-NAV-01` 由 4 目的地改为抽屉式 IA）。
- 收集箱（inbox）与项目清单统一收纳在抽屉内，与滴答「系统预设 + 用户清单」分组一致。
- 路由不变（`/inbox /today /calendar /projects /tags` 仍存在），仅入口位置变化；抽屉选中态由当前路由推导。

### 3.2 宽屏（≥600dp）：NavigationRail 保留

- Rail 保持 5 目的地（收集箱/今日/日历/项目/标签）+ master-detail 两栏，宽度 80 → 96。
- 选中态：药丸高亮（浅色背景 + 圆角），图标 outlined/filled 对。

### 3.3 需求文档联动

- `10-requirements.md` `FR-NAV-01`：改为「移动端抽屉 + 宽屏 NavigationRail」；`FR-NAV-02` 不变。
- `50-ui-ux.md` §4 同步更新。

## 4. 添加任务交互（D2 细化）

### 4.1 移动端新建（底部弹窗）

```
FAB（右下圆形蓝色 + 白加号）→ 底部弹窗（圆角 16–20，顶部圆角）：
├─ 顶部行：清单名（下拉箭头，点击弹「移动到」清单选择）  [旗帜优先级] [⋯]
├─ 标题输入（18–20sp / w600，无边框，占位符「任务标题」）
├─ 选项行（[图标] 文字 ……… 右侧值/箭头）：
│   日期与提醒（日历图标）→ 底部日期选择器（今天/明天/下周/自定义）
│   优先级（旗帜图标）→ 红/橙/蓝/无 循环或选择
│   标签（标签图标）→ 药丸多选 + 新建
├─ 子任务区（可选：圆形复选框 + 拖拽排序 + 新增行）
└─ 自动保存：失去焦点/关闭时保存（标题为空则丢弃或提示）
```

- 键盘弹出：内容区滚动保持输入可见；弹窗随键盘上移（`isScrollControlled` + `viewInsets`）。
- 宽屏：FAB 移至 AppBar「+」或 Rail 底部，新建用居中对话框（同字段结构）。

### 4.2 编辑已有任务：保留全屏页

- `task_edit_page.dart` 结构不变，仅视觉随令牌自动适配（基底/圆角/选项行样式）。

## 5. 设计令牌变更（批 1 落地）

```dart
// lib/core/theme/app_tokens.dart 变更草案
// 页面基底（新增）
surfacePage        浅灰（light: #F2F4F7 / dark: #0F1117）—— 页面 Scaffold 背景
// 卡片层级（调整）
radiusCard          16（卡片行圆角）
cardElevation       0.5 → 1.0（卡片轻微抬升；hover 2.0）
// 圆形复选框（新增/调整）
checkboxShape       圆形（radiusCheckbox 移除，改用圆形）
checkboxDoneFill    colorInProgress（蓝填充 + 白勾）
// 进度环（新增）
progressRingSize    24
progressRingWidth   2.5
// 抽屉（新增）
drawerWidthRatio    0.78
drawerSelectedBg    浅色药丸背景（colorScheme.primaryContainer 派生）
```

> 禁止魔法值；明暗两套由 `ColorScheme.fromSeed` 派生，语义色保持可辨识。

## 7. 实施批次与验收

### 批 1 — 视觉层（纯表现，无数据流/路由变更）

1. 令牌：surfacePage / 卡片层级 / 圆形复选框 / 抽屉令牌。
2. 主题：基底与卡片 elevation 接入。
3. `SimpleTaskTile` + 任务树行：圆形复选框 + 卡片化。
4. 各视图页面基底适配。
5. 宽屏 Rail 打磨（宽度/选中态）。

**验收**：`flutter analyze` 0 error；`flutter test` 全绿；双端手工走查（今日/日历/项目树/标签/搜索/编辑页）视觉一致、无回归。

### 批 2 — 交互层（IA 变更，需先改需求文档）

1. `FR-NAV-01` 更新 + `50-ui-ux.md` §4 同步。
2. 移动端抽屉组件（系统组 + 项目组 + 添加项目）。
3. FAB + 新建底部弹窗（自动保存 + 清单切换 + 日期/优先级/标签）。
4. 进度环（有子任务任务）。
5. 同步状态图标（依赖 M4 完成）。

**验收**：批 1 全绿 + 抽屉导航正确 + 新建弹窗全流程（含键盘适配、自动保存、校验）+ 进度环正确 + 双端手工回归。

## 8. 明确不做（v1 外）

- 不做滴答式「提醒/通知」「重复任务」「背景图」「清单 emoji 图标系统」（数据模型无此字段，AGENTS.md §3-5）。
- 不做深色模式纯黑背景（保留 `surface` 令牌，`50-ui-ux.md` §8）。
- 不做桌面端三栏布局重构（现有两栏 master-detail 保留）。
- 不做任务详情页的滴答式「无保存按钮自动保存」（编辑页保留显式保存，字段多易误触）。
