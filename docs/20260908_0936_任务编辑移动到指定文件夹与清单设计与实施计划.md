# 任务编辑界面支持选择文件夹和清单（跨项目移动）设计与实施计划

## 1. 需求背景与核心目标

### 1.1 需求描述
用户在**任务编辑界面**中，希望能够通过「项目」这一属性行，浏览并选择**指定的文件夹**以及**其下的清单（项目）**，从而实现将当前正在编辑的任务**移动到指定清单内**的目的。

### 1.2 现状剖析
1. **数据与持久化层问题**：
   - `TodoRepository.moveTaskToProject(taskId, newProjectId)` 虽然已存在原型，但**仅更新了根任务自身的 `projectId`，未级联更新其子任务和孙任务的 `projectId`**。若任务包含子任务，跨项目移动后会导致子任务丢失或成为孤儿节点。
   - `TaskFormNotifier` 在 `save()` 时**完全没有处理 `projectId` 的变更**（仅调用了 `updateTask`，而 `updateTask` 不接受 `projectId`），导致编辑态在前端选了新项目也无法落库。
   - `TaskFormNotifier` 未追踪 `_originalProjectId`，导致 `hasChanges` 无法感知项目变动。
2. **交互与选择器（`ProjectPickerSheet`）问题**：
   - 现有的 `ProjectPickerSheet` 仅为扁平的 `ListView.builder`，把所有项目平铺列出，**完全没有展示文件夹（Folder）分组层级**，用户无法按文件夹找寻清单。
   - 现有的 `ProjectPickerSheet` 遗漏了系统内置「收件箱（`inboxProjectId`）」的选择入口。
3. **任务编辑界面（`TaskEditPage` / `TaskEditor`）问题**：
   - `TaskEditPage` 顶部 AppBar 中的 `TaskProjectSwitcher` 被硬编码为 `interactive: !_isEditing`（因历史原因跨项目移动未完备而禁用）。
   - 编辑器详情模式（`_buildDetailsMode`）中「所属项目」行只展示了清单名称，若清单属于某个文件夹，没有展示文件夹名称上下文（如 `工作 / 需求清单`）。

## 2. 关键架构设计与技术决策

### 2.1 决策 1：文件夹与清单的层级与归属语义
- **数据模型约束**：在系统中，`Folders` 为单层文件夹表，`Projects` 为清单表（`folderId` 指向文件夹，为 NULL 则为未分组），`Tasks` 为任务表（`projectId` 指向清单，为 NOT NULL）。
- **移动语义**：任务隶属于**清单（Project）**，不直接隶属于文件夹。因此：
  - 用户在弹层中可以**按文件夹浏览**（展开/折叠文件夹）其所包含的清单；
  - 最终选中的移动目标是**具体的清单**（包含：收件箱、某个文件夹下的清单、未分组清单）；
  - 任务不能直接挂载到「空文件夹」，若文件夹无清单，可提示 `(无清单)` 或提供「+ 新建清单」。

### 2.2 决策 2：跨项目移动的树状子任务一致性保证
- 当任务 `taskId` 被移动至 `newProjectId` 时：
  1. 该任务若在原项目为子任务（`parentId != null`），因父任务不能跨项目（AGENTS.md §3-1），其 `parentId` **置为 `null`**，成为目标项目的根任务（1 级任务）。
  2. 递归查找该任务在原项目的所有后代任务（子任务、孙任务）。
  3. 将该任务及其所有后代任务的 `projectId` **原子更新为 `newProjectId`**，同时刷新 `updatedAt` 为当前 UTC 毫秒，保证多端同步能够接收到更新。
  4. 内部各级子任务之间的相对 `parentId` 和 `sortOrder` 保持不变，树深不会增加（根任务变 1 级，最大深度仍 $\le 3$ 级，严格符合 AGENTS.md §3-1 约束）。

### 2.3 决策 3：保存时机与延迟提交策略
- 与编辑界面的既有设计保持一致（`D2` 显式保存/返回拦截自动保存）：
  - 用户在选择器中选中目标清单后，更新 `taskFormProvider` 中的 `projectId`（并置 `parentId` 为 `null`）；
  - 界面上的「所属项目」行与顶部栏即时响应，展示新清单（及文件夹）信息；
  - 此时 `hasChanges` 变为 `true`；
  - 当用户点击「保存」或返回退出时执行 `save()`，在同一个保存流中先执行 `_repo.moveTaskToProject`，再更新其它字段和同步子任务，避免用户若误点后取消却意外修改了数据库。

### 2.4 决策 4：选择器（`ProjectPickerSheet`）交互规范
- **结构规范**：
  1. **顶部导航**：关闭按钮 + 标题「移动到」 + 搜索框（支持搜索清单名与文件夹名）。
  2. **收件箱（Inbox）**：置顶展示系统内置收件箱（`inboxProjectId`），带收件箱图标，若当前在此项目则显示对勾。
  3. **文件夹组**：
     - 每个文件夹一行：折叠/展开指示箭头（`Icons.keyboard_arrow_down` / `keyboard_arrow_right`） + 文件夹图标 + 文件夹名 + 清单计数徽标。
     - 点击文件夹行：展开/折叠内部清单（默认全部展开，便于快速查阅）。
     - 展开区域：缩进展示该文件夹下的各清单，含颜色圆点、清单名、当前所在清单对勾标记。点击清单即选中并关闭弹层。
  4. **未分组清单**：
     - 分组标题「未分组」，下方展示所有未归属于任何文件夹的普通清单。
  5. **搜索模式**：
     - 用户输入文本时实时过滤，展示匹配的清单并附带文件夹副标题（例如 `工作 / 待办`），无结果时显示「未找到相关内容」。
  6. **底部操作**：
     - 「+ 添加项目」入口，支持一键调用新建清单模态弹层，创建完成后直接选中。

### 2.5 决策 5：编辑界面「所属项目」行的视觉呈现
- 在 `TaskEditor` 详情模式属性卡片及 `TaskProjectSwitcher` 中：
  - 若 `project.folderId != null`，显示为：`{文件夹名} / {清单名}`；
  - 若未分组，显示为：`{清单名}`；
  - 若为收件箱，显示为：`收件箱`；
  - 使得用户一眼便能感知当前任务所处的「文件夹」与「清单」完整路径。
- 将 `TaskEditPage` 中的 `TaskProjectSwitcher(interactive: !_isEditing)` 改为 `TaskProjectSwitcher(interactive: true)`，允许顶部栏与信息行均可点击切换。

1. **底层移动校验**：
   - 验证单任务跨项目移动，目标项目内 `sortOrder` 正确连续；
   - 验证带 1 级子任务、2 级孙任务的任务整棵子树移动，移动后所有子节点 `projectId` 均变更为目标项目，且原有的父子依赖树结构完好；
   - 验证原本为子任务的任务跨项目移动后，`parentId` 被清空为 `null`，脱离原父任务；
   - 验证向已删除或不存在的项目移动时抛出预期的 `RepositoryException`。

   - 点击保存，验证数据库中该任务已成功移入新清单；
   - 再次进入该任务，确认所属项目为新清单。
